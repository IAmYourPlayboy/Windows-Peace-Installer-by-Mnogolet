# Архитектура Razvert

## 1. Проблема

Ручное развёртывание кастомной Windows 11 занимает около трёх часов, из которых значительная часть — обход двух дефектов Windows Setup.

### Дефект A — установка уходит не на тот диск

`DiskID` в `autounattend.xml` — это **порядковый номер перечисления** в storage-стеке, а не идентификатор устройства. Он зависит от порядка инициализации контроллеров, соотношения NVMe и SATA, настроек прошивки, и может меняться между загрузками одной и той же машины. Указание конкретного номера не даёт гарантий; отсюда практика физически отключать лишние диски.

### Дефект B — установилась Windows 11, загружается прежняя Windows 10

Более коварный, потому что выглядит как «установка молча не сработала». Реальный механизм:

1. Windows Setup записывает загрузчик в **первый найденный EFI System Partition**, а не обязательно в ESP целевого диска.
2. Setup **не приводит в порядок NVRAM прошивки**. Существующая запись загрузки, указывающая на старую систему, остаётся первой в порядке.
3. Машина перезагружается и честно грузит то, что стоит первым — старую систему. Новая при этом установлена и лежит на диске.

Обход через предварительное форматирование всех дисков установщиком Windows 10 работает по случайности: он уничтожает конкурирующие ESP, и первым остаётся только нужный.

**Оба дефекта — следствие того, что решение о размещении принимает Setup, а не мы.**

## 2. Ключевое решение

Не использовать `setup.exe`. Развернуть образ самостоятельно из WinPE:

```
WinPE
 └─ Razvert.Pe
     ├─ перечислить диски и идентифицировать их по отпечатку
     ├─ выбрать целевой (человеком или по правилу)
     ├─ разметить GPT: ESP → MSR → Windows → Recovery
     ├─ Dism /Apply-Image из install.wim
     ├─ Dism /Add-Driver офлайн в применённый образ
     ├─ bcdboot на ESP ЭТОГО диска
     ├─ привести в порядок NVRAM: убрать мёртвые записи, поставить новую первой
     ├─ положить unattend.xml, агент и рецепт
     └─ reboot
```

Пасс `windowsPE` в `unattend.xml` не нужен вообще — остаются только `specialize` и `oobeSystem`.

Дефект A устраняется тем, что диск адресуется отпечатком (`SerialNumber` + `Model` + `SizeBytes` + `BusType`), а не номером.
Дефект B устраняется явным управлением ESP и NVRAM.

Побочный результат: вторая установка Windows и выдёргивание дисков из корпуса больше не нужны.

## 3. Тонкий unattend

Atlas официально ставится на **чистую немодифицированную Windows**; предварительный дебloat ломает логику плейбука. Поэтому `unattend.xml` содержит только то, без чего установка не пройдёт без человека:

локаль, раскладки, часовой пояс, локальная учётная запись, пропуск OOBE / привязки к Microsoft-аккаунту / экранов приватности, при необходимости — обход проверок железа.

Всё остальное переезжает в `Razvert.Agent` и выполняется **после** Atlas. Дополнительный эффект: тонкий unattend не требует правки при каждой смене билда Windows.

## 4. Компоненты

Три исполняемых компонента, потому что они физически живут в разных средах. Связывает их один файл рецепта.

| Компонент | Среда | Ответственность |
|---|---|---|
| `Razvert.Studio` | Обычная Windows | Конструктор рецепта. Скачивание ISO и полезной нагрузки с проверкой SHA256, сборка `boot.wim`, генерация `unattend.xml`, запись USB |
| `Razvert.Pe` | WinPE | Выбор диска, разметка, применение образа, драйверы, загрузчик, NVRAM, засев агента |
| `Razvert.Agent` | Установленная Windows | Машина состояний поверх перезагрузок: драйверы → Windows Update → Atlas → Windhawk → приложения → твики → самоочистка |
| `Razvert.Core` | Библиотека | Модель рецепта, валидация, движок шагов, логирование |

### Поток данных

```
recipe.json ──┬──> Studio  ──> USB (boot.wim + install.wim + payload + recipe.json)
              │
              ├──> Pe      ──> C:\ProgramData\Razvert\{recipe.json, agent, payload}
              │
              └──> Agent   ──> state.json (прогресс, переживающий перезагрузки)
```

Рецепт неизменен на всём пути. Изменяемое состояние живёт только в `state.json`.

## 5. Принятые решения

| Решение | Обоснование | Цена |
|---|---|---|
| Применять образ через DISM вместо `setup.exe` | Единственный способ детерминированно управлять размещением и загрузчиком | Разметку и BCD пишем и тестируем сами |
| Диск по отпечатку, номер не используется нигде | Номер нестабилен по устройству | Требуется UI выбора и осмысленная обработка неоднозначности |
| Явное управление NVRAM прошивки | Прямое лечение дефекта B | Работа с `bcdedit /enum firmware`, риск на нестандартных прошивках |
| Тонкий `unattend.xml` | Требование Atlas + устойчивость к смене билдов | Больше логики в агенте |
| Рецепт как единый контракт | Новая конфигурация = новый JSON, а не правка кода | Схему надо версионировать и мигрировать |
| Типизированные шаги пост-установки | Новая возможность = новый тип шага, движок не трогается | Дисциплина: `script.run` — аварийный люк, а не норма |
| C# / .NET Framework 4.8 + WPF | Единственный управляемый UI-стек, работающий в WinPE (`WinPE-NetFx`). Один язык на все компоненты | WPF в WinPE официально не поддерживается Microsoft; рендер программный |
| Полезная нагрузка скачивается, а не хранится | Юридическая чистота и воспроизводимость | Нужна сеть на этапе сборки и фиксация хешей |
| Только UEFI + GPT | Вдвое меньше кода разметки и тестовых конфигураций | Старые машины пока вне охвата; форма рецепта готова к расширению |

## 6. Ограничения WinPE

Компоненты добавляются в образ в этом порядке — между ними есть зависимости:

```
WinPE-WMI → WinPE-NetFx → WinPE-Scripting → WinPE-PowerShell
→ WinPE-StorageWMI → WinPE-DismCmdlets
→ WinPE-SecureStartup → WinPE-EnhancedStorage
```

- `Dism /Set-ScratchSpace:512` — иначе .NET не запустится на стандартных 32 МБ.
- Разрешение экрана задаётся отдельным unattend для `Microsoft-Windows-Setup`.
- Аппаратного ускорения нет. Анимации допустимы на opacity и transform; blur, крупные тени и градиенты во весь экран — нет.
- Кириллица в UI требует проверки наличия шрифтов в базовом образе.

## 7. Что осознанно не делается

- **Не обещается полностью автоматический Atlas.** У AME Wizard нет документированного CLI. Официальный ISO-injection существует, но экспериментален и ограничен Windows 11 25H2 и Playbook 0.5.0+. Стратегия задаётся в рецепте и деградирует мягко — вплоть до «агент подготовил всё, нажми три кнопки».
- **Не распространяются ISO Windows и плейбук Atlas.** Только скачивание с официальных источников. Лицензия Windows — на стороне пользователя.
- **Не поддерживается Windows Home.** Atlas на нём не ставится.
- **Не поддерживается Legacy BIOS + MBR** в первой версии.

## 8. Безопасность

Инструмент предназначен для раздачи незнакомым людям и форматирует диски с их данными. Значения по умолчанию выбраны в пользу осторожности:

- носитель, с которого загрузился WinPE, исключается жёстко;
- перед разметкой человек вручную вводит модель целевого диска;
- обнаружение томов с данными или другой установленной Windows по умолчанию требует подтверждения;
- `wipeOtherEsps` по умолчанию выключен: он ломает мультизагрузку с Linux;
- `dryRun` проходит весь путь и показывает план, ничего не записывая;
- любой сбой оставляет полный лог, пригодный для отправки в поддержку.
