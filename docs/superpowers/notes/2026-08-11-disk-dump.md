## Главный результат: серийные номера читаются

На всех трёх дисках серийный номер взят из **первого же источника цепочки** —
`MSFT_PhysicalDisk.SerialNumber`, — и уровень доверия вышел `Hardware`. Ни одного
отката на `UniqueId` или на GUID разметки не понадобилось.

Это важно: вся архитектура стоит на том, что диск адресуется отпечатком, а не
порядковым номером ([ARCHITECTURE.md, дефект A](../../ARCHITECTURE.md)). На настоящем
железе автора приём работает, включая USB-флешку.

Открытым остаётся вопрос про **виртуальные диски Hyper-V** — он решается на шаге В.

## Найденный дефект: Windows не находилась вовсе

Первый прогон показал `Windows=False` на всех разделах, включая раздел с работающей
прямо сейчас системой.

Причина. Спека предписывала считать Windows установленной по файлу
`\Windows\System32\config\SYSTEM`. Этот куст реестра закрыт правами доступа: под
обычной учётной записью `File.Exists` отвечает `false` даже там, где Windows заведомо
стоит. Проверено напрямую:

| Путь | `File.Exists` |
|---|---|
| `C:\Windows\System32\config\SYSTEM` | False |
| `C:\Windows\System32\ntoskrnl.exe` | True |
| `D:\Windows\System32\config\SYSTEM` | False |
| `D:\Windows\System32\ntoskrnl.exe` | True |

В WinPE проверка сработала бы — там программа работает от системы. Но шаг А живёт
на обычной Windows, и там она не работает никогда.

Цена ошибки конкретная: на диске D: стоит вторая Windows. Инструмент сказал бы, что
её нет, и не показал бы предупреждение «всё будет стёрто безвозвратно». Это ровно то
молчаливое поведение, которое запрещено [разделом 9 архитектуры](../../ARCHITECTURE.md).

Исправление: к кусту реестра добавлен второй признак — файл ядра
`\Windows\System32\ntoskrnl.exe`. Он есть в любой установленной Windows и читается
кем угодно. Куст остаётся первым: на шаге В из него будут читаться издание и версия.
Закрыто тестом `Windows_находится_по_ядру_когда_куст_реестра_недоступен`.

После правки `Windows=True` на обоих разделах с системой.

## Сверка с «Управлением дисками»

- [ ] Число дисков, объёмы, число и размеры разделов, буквы — сверяет автор.
- [ ] Диск с работающей системой помечен `система: True` — сверяет автор.
- [ ] Флешка помечена `съёмный: True` — сверяет автор.

Что видно без сверки и выглядит правдоподобно: у обоих внутренних дисков полная
разметка Windows (EFI, MSR, данные, восстановление), у флешки два раздела и шина USB,
незанятых промежутков нет ни на одном диске.

Отметка «носитель Windows Peace» везде `False` — правильно: файла
`windows-peace-media.json` пока не существует нигде, он появляется на шаге Б.
