# Дорожная карта

Порядок выбран так, чтобы работающая ценность появлялась как можно раньше, а самый большой технический риск снимался до того, как на нём будет построен код.

## Фаза 0 — Стенд

Виртуальная машина Hyper-V: UEFI, Secure Boot, TPM, **четыре диска разного размера**, снапшоты для мгновенного отката.

Отдельный сценарий «грязная машина»: на одном из дисков предустановленная Windows 10 с собственным EFI-разделом. Это воспроизводит дефект B — установка проходит, а грузится прежняя система.

Без стенда каждая проверка стоит три часа на живом железе, и проект умирает на третьей неделе. Со стендом — двадцать минут.

**Готово, когда:** одной командой поднимается чистая машина, одной — «грязная».

## Фаза 1 — Спайк WinPE + WPF

Снимает главный технический риск: WPF в WinPE официально Microsoft не поддерживается.

Сборка `boot.wim` из ADK с нужными компонентами в правильном порядке, `Set-ScratchSpace:512`, подмена `winpeshl.ini`.

**Готово, когда:** в WinPE стартует WPF-приложение, показывает список дисков из `Get-Disk`, анимация не тормозит на программном рендере.

Если WPF окажется нежизнеспособен — запасные варианты HTA и WinForms, но решение принимается здесь, а не после написания UI.

## Фаза 2 — Движок развёртывания

Ядро ценности. Идентификация дисков по отпечатку, исключение загрузочного носителя, разметка GPT, `Dism /Apply-Image` с реальным прогрессом, офлайн-инъекция драйверов, `bcdboot` на собственный ESP, приведение в порядок NVRAM.

**Готово, когда:** на «грязной» машине из Фазы 0 установка уходит на выбранный диск и машина грузится в новую систему. Ни один диск не отключался физически.

С этого момента процедура уже окупилась, даже если остальное не будет сделано.

## Фаза 3 — Unattend и агент

Генератор тонкого `unattend.xml`. `Razvert.Agent`: `state.json`, запланированная задача, автовход с ограниченным счётчиком, идемпотентные возобновляемые шаги, самоочистка.

**Готово, когда:** после развёртывания машина сама доходит до рабочего стола и выполняет цепочку шагов через несколько перезагрузок.

## Фаза 4 — Atlas, Windhawk, приложения

Типизированные шаги. Три стратегии Atlas с мягкой деградацией. Windhawk silent-установкой и предзасевом модов. Приложения через winget.

**Готово, когда:** полный проход от вставленной флешки до настроенной системы.

## Фаза 5 — Studio

GUI-конструктор, скачивание с проверкой хешей, сборка носителя.

**Готово, когда:** рецепт собирается мышкой, без ручного редактирования JSON.

## Фаза 6 — Публичная раздача

Всё из отдельной задачи по безопасности и юридической чистоте: подпись бинарников, выгрузка лога для поддержки, документация, обработка чужих ошибок и чужого железа.

Веб-конфигуратор, отдающий готовый рецепт, — естественное продолжение Studio. Контракт под это уже рассчитан.
