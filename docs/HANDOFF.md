## Что за проект

Windows Peace — инструмент развёртывания настроенной Windows 11. Раньше назывался Razvert, переименован 10.08.2026.

Три части, так их видит автор:

1. **`WindowsPeace.Studio`** — программа на обычном компьютере. Скачивает Windows, делает из флешки установочный носитель, кладёт на неё один или несколько рецептов.
2. **`WindowsPeace.Setup` и `WindowsPeace.Agent`** — мастер установки с глубокой настройкой и доводка системы после. Здесь ядро ценности и весь технический риск, поэтому делается первой.
3. **Мини-сайт документации** — в самом конце.

Проект меценатский: планируется сайт, где незнакомым людям бесплатно предлагают установить настроенную систему.

## Что произошло в прошлой сессии

### Нашёлся рабочий autounattend.xml автора

Лежал на `E:\autounattend.xml` — его загрузочной флешке. 811 строк, генератор [cschneegans/unattend-generator](https://github.com/cschneegans/unattend-generator), режим `PEMode=Generated`.

**Он подтвердил обе гипотезы проекта и уточнил одну из них.** Разбор целиком — в [ARCHITECTURE.md, раздел 1](ARCHITECTURE.md). Главное:

- дефект A подтверждён буквально: в скрипте стоит `SELECT DISK=0`;
- дефект B оказался не тем, чем считался. Загрузчик пишется **правильно**, в ESP целевого диска. Ломается строка `bcdedit /set {fwbootmgr} bootsequence {bootmgr}` — она задаёт одноразовый `BootNext`, а не постоянный `BootOrder`. Отсюда возврат к прежней системе на второй перезагрузке.

**Механизм прочитан в коде, но на стенде ещё не воспроизведён.** Подтверждение — критерий готовности шага В. Не считай его доказанным.

### Прочитано содержимое boot.wim установочного носителя

Через 7-Zip, без прав администратора. Опись — в [ARCHITECTURE.md, раздел 6](ARCHITECTURE.md).

Внутри уже есть всё, чем инструмент делает работу: `StorageWMI`, `diskpart`, `dism`, `wimgapi`, `bcdboot`, `bcdedit`, `drvload`, драйверы NVMe, `mshta`. **Нет среды выполнения для интерфейса**: `Microsoft.NET` — пустая заглушка, PowerShell представлен одними модулями без движка.

Отсюда решение автора: базовый образ **берётся из ISO и правится**, а не собирается из ADK. Это дало три выигрыша разом — драйверы уже есть, ADK может не понадобиться вовсе, и раздача становится юридически чистой, потому что Studio собирает носитель на машине пользователя из его собственного ISO.

### Правки в контракте

- `unattend.locale` разбит на `uiLanguage`, `systemLocale`, `userLocale`, добавлен `geoLocation`. Причина: у автора три разные локали осознанно — русский интерфейс на системной локали `en-US`.
- Описание `bootCleanup` переписано под настоящий механизм дефекта B.

### Отказоустойчивость стала обязательством

По прямому требованию автора: ничто не должно зависать намертво, ничто не должно ломаться молча. [ARCHITECTURE.md, раздел 9](ARCHITECTURE.md) — семь правил, у каждого прописан способ проверки. Ключевое — сторожевой таймер: операция, переставшая отчитываться о продвижении, объявляется зависшей и прерывается.

Аргумент автора, который надо помнить: базовый `boot.wim` весит 680 МБ, на его фоне проверки и журналы не стоят ничего. **Экономить на обработке ошибок незачем.**

## Решения автора — не переспрашивай

| Вопрос | Ответ |
|---|---|
| Версия Windows | Windows 11 Pro 25H2, значит `isoInjection` для Atlas доступен |
| Режим загрузки | Только UEFI + GPT |
| Порядок работ | Сначала окно, потом WinPE, потом запись на диск. Стенд Hyper-V строится к шагу В, не раньше |
| Разделы в интерфейсе | Список двухуровневый, кнопки «Создать», «Удалить», «Форматировать», «Расширить» **остаются**. Довод автора: «я не имею права говорить пользователям, что им это не нужно» |
| Раскладка экрана | По смыслу как в установщике Windows. Визуал автор настраивает сам |
| Несколько Windows | Имеется в виду **несколько рецептов на одной флешке**, а не мультизагрузка. Механика Ventoy не нужна: загрузочная часть наша |
| Среда выполнения | Самодостаточное .NET 8. Допущение до опыта на шаге Б |
| Целевые платформы | `Core` — `net48;net8.0-windows`, `Setup` — только `net8.0-windows` |

## Открытые вопросы

Не выдавай их за решённые.

1. **Читаются ли серийные номера у виртуальных дисков Hyper-V.** На отпечатке стоит вся модель адресации дисков. Ответ появится на шаге В. Уровни доверия к отпечатку введены заранее именно потому, что ответ может быть отрицательным.
2. **Заработает ли самодостаточное .NET 8 в WinPE.** Шаг Б. Если нет — запасные пути: `WinPE-NetFx` из ADK, затем HTA.
3. **Переживает ли NVRAM гостя чекпоинт и экспорт Hyper-V.** От этого зависит устройство грязного сценария на шаге В.

## Как работать над этим проектом

Прямые указания автора. Соблюдай их — за нарушение первого он уже делал замечание.

- **Объясняй приземлённо.** Не «NVRAM хранит BootOrder», а «материнская плата помнит, откуда грузиться». Термин вводи один раз и сразу переводи. При выборе из вариантов пиши конкретно: что делаю я, что делаешь ты, сколько времени, что получишь, что при этом плохо.
- **Качество и логика важнее краткости.** Думать столько, сколько нужно; скорость не важна. Но изложение — человеческое.
- **Никакой кустарщины.** Только систематические решения, рассчитанные на долгую жизнь.
- **Дробить на подзадачи.** Понемногу, постепенно.
- **Сначала видимое, потом оснастка.** Автор возразил на предложение начать со стенда, и был прав. Проверяй порядок работ вопросом «что автор увидит в конце этого шага».
- **Не отбирать у пользователя возможности** со словами «это вам не нужно».
- **Спрашивать, если ответ меняет архитектуру.** Не угадывать.
