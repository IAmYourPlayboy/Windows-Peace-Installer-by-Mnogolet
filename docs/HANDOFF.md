# Часть первая: где мы остановились

## Главное: риск проекта снят

**WPF в WinPE работает.** Проверено 14.08.2026 опытом на стенде Hyper-V, а не
рассуждением. Самодостаточное .NET 8 запускается, окно рисуется, кириллица
на месте, аппаратное ускорение не нужно. Сработал первый из трёх путей —
ни ADK, ни HTA не понадобились. Целевая версия .NET во всём проекте прежняя.

Снимки экрана: [консоль в WinPE](superpowers/notes/2026-08-14-pe-diskdump.png),
[окно мастера](superpowers/notes/2026-08-14-pe-window-native.png).

## Второе: WMI из управляемого кода в WinPE не работает, и это уже вылечено

`System.Management` несамостоятельна — она подгружает `wminet_utils.dll`
из .NET Framework 4.8, а в WinPE папка `Microsoft.NET` пустая. Сам WMI в образе
цел; сломан мост между ним и .NET Core.

По решению автора перечисление дисков переведено на **прямой разговор с Windows**:
диск открывается как устройство и сам сообщает модель, серийный номер, шину
и разметку; тома, буквы и свободное место берутся отдельными вызовами.
Ни WMI, ни COM, ни .NET Framework.

| Что | Где |
|---|---|
| Плоское описание того, что отдало ядро | `Core/Storage/Native/RawStorage.cs` |
| Объявления вызовов Windows | `Core/Storage/Native/NativeMethods.cs` |
| Настоящий разговор с ядром | `Core/Storage/Native/Win32StorageSource.cs` |
| Сборка модели дисков, закрыта тестами | `Core/Storage/NativeDiskEnumerator.cs` |

**Сверено на живой машине автора.** `DiskDump` печатает оба перечислителя
и сличает их поле за полем. Серийные номера трёх дисков, уровень доверия,
модели, объёмы, шины, тип носителя, признаки системного и съёмного диска,
смещения и размеры всех десяти разделов, буквы — совпали. Время упало
с 240–1152 мс до **11 мс**.

Четыре расхождения остались, и все в пользу прямого источника: он видит
файловую систему разделов EFI и восстановления, у которых нет буквы диска.

**`WmiDiskEnumerator` больше не используется приложением, но оставлен ради
сличения.** Убирать ли его вместе с зависимостью от `System.Management` —
решать в конце шага, спросив автора.

## Что подтвердилось попутно

- **Носитель опознаёт сам себя.** `BootMediaLocator` нашёл опись, диск помечен
  «Загрузочный носитель — установка сюда невозможна». Код с шага А включился
  без единой правки, как только появился файл описи.
- **У виртуальных дисков Hyper-V серийного номера нет.** Отпечаток откатывается
  на идентификатор из разметки, доверие честно понижается до `Volatile`.
  Открытый вопрос проекта закрыт. **Вывод для шага В: стенд не годится
  для проверки отпечатков, это делается только на настоящем железе.**
- **Носитель нашей разметки грузится.** Прошивка приняла скрытый раздел
  «системный EFI» на виртуальном диске при включённой безопасной загрузке.
- **Разрешение экрана WinPE — 1024×768.** Окно 1024×720 влезает.
- **Раздел данных получил в WinPE букву `C:`.** Букв в WinPE ждать нельзя;
  поиск по описи в корне каждого раздела остаётся единственным надёжным.
- **Обычного начертания Segoe UI в образе нет** — есть жирное, курсив и светлое.
  В разметке оболочки задана цепочка `Segoe UI, Tahoma, Microsoft Sans Serif`.
  Текст в WinPE читается; отдельно подключать шрифт пока не потребовалось.

# Часть вторая: как пользоваться стендом

Это самое ценное, что осталось от сессии. Круг проверки — около трёх минут,
и автор в нём не участвует.

## Полный круг: пересобрать и посмотреть

```powershell
cd D:\Projects\WindowsPeace

dotnet publish src\WindowsPeace.Setup -c Release -r win-x64 --self-contained true -o artifacts\setup

Stop-VM -Name 'Windows Peace Stand' -TurnOff -Force -ErrorAction SilentlyContinue
Remove-VM -Name 'Windows Peace Stand' -Force -ErrorAction SilentlyContinue

powershell -File tools\Media\Build-PeaceMedia.ps1 -VhdxPath D:\WindowsPeace-Stand\peace.vhdx `
    -AppFolder artifacts\setup -DiskDumpFolder artifacts\diskdump -SkipInstallWim
powershell -File tools\Media\New-PeaceVm.ps1 -VhdxPath D:\WindowsPeace-Stand\peace.vhdx
Start-VM -Name 'Windows Peace Stand'
Start-Sleep -Seconds 50

powershell -File tools\Media\Send-PeaceVmKeys.ps1 -ShiftF10
Start-Sleep -Seconds 5
powershell -File tools\Media\Send-PeaceVmKeys.ps1 -Enter `
    -Text 'for %d in (C D E F G H I) do @if exist %d:\windows-peace-media.json set P=%d:'
Start-Sleep -Seconds 2
powershell -File tools\Media\Send-PeaceVmKeys.ps1 -Text '%P%\WindowsPeace\WindowsPeace.Setup.exe' -Enter
Start-Sleep -Seconds 35

powershell -File tools\Media\Get-PeaceVmScreen.ps1 -OutPath D:\WindowsPeace-Stand\screen.png
```

Дальше просто открой PNG — на нём видно всё, что нарисовалось в WinPE.

## Забрать журнал с носителя

Виртуалку надо сначала выключить и снять с неё диск, иначе он занят:

```powershell
Stop-VM -Name 'Windows Peace Stand' -TurnOff -Force
Remove-VM -Name 'Windows Peace Stand' -Force
$n = (Mount-VHD -Path D:\WindowsPeace-Stand\peace.vhdx -Passthru | Get-Disk).Number
$d = (Get-Partition -DiskNumber $n | Where-Object DriveLetter).DriveLetter
Get-Content "${d}:\WindowsPeace\logs\windows-peace.jsonl"
Dismount-VHD -Path D:\WindowsPeace-Stand\peace.vhdx
```

## Сличить два перечислителя на обычной Windows

```powershell
dotnet run --project tools\DiskDump
```

Печатает WMI, прямой источник и список расхождений между ними. Ключи `--wmi`
и `--native` оставляют один. **Прогоняй это после каждой правки в `Native/`** —
сличение уже поймало одну настоящую ошибку.

## Что знать про эти скрипты

- Все они требуют прав администратора и проверяют это первой строкой.
- `Build-PeaceMedia.ps1` откажется работать, если виртуальный диск занят
  виртуалкой, и назовёт её по имени. Так и задумано.
- Ключ `-SkipInstallWim` пропускает копирование девяти гигабайт. До шага В
  образ Windows на носителе не нужен.
- Номер издания внутри `install.wim` ищется **по имени**, а не задаётся числом.
  В образе автора под первым номером лежит Домашняя, а Pro — под вторым.
- Загрузочный раздел прячется двумя действиями: снять букву, потом сменить тип
  на «системный EFI». Одной смены типа мало — Windows букву сама не отзывает.

# Часть третья: что нужно знать о проекте и машине

## Что за проект

Windows Peace — инструмент развёртывания настроенной Windows 11. Три части:
`Studio` (готовит флешку), `Setup` + `Agent` (мастер установки и доводка),
мини-сайт документации. Общие для всех — `WindowsPeace.Core` и файл рецепта.

Проект меценатский: планируется сайт, где незнакомым людям бесплатно предлагают
установить настроенную систему. Отсюда все решения в пользу осторожности.

## Права администратора

**Есть, но добывались с трудом.** Приложение Claude надо не просто закрыть,
а завершить полностью через значок у часов, и только потом запускать правой
кнопкой → «Запуск от имени администратора». Закрытие окна процесс не завершает,
и права не появляются.

Проверить: `([Security.Principal.WindowsPrincipal][Security.Principal.WindowsIdentity]::GetCurrent()).IsInRole([Security.Principal.WindowsBuiltInRole]::Administrator)`

Если не выйдет — запасной путь: автор открывает «Терминал (Администратор)»
и запускает оттуда `%APPDATA%\Claude\claude-code\<версия>\claude.exe --resume`.

## Открытые вопросы

Не выдавай их за решённые.

1. **Хватит ли цепочки запасных шрифтов** на настоящем железе. В виртуалке текст
   читается, но обычного Segoe UI в образе нет, и это надо посмотреть глазами.
2. **Перекроет ли `winpeshl.ini` запуск установщика Windows,** или придётся
   править куст реестра внутри образа. Задача 13 плана, там же запасной приём.
3. **Как поведут себя настоящие прошивки** с разделом «системный EFI»
   на съёмном носителе. На виртуалке — образцово.
4. **Переживает ли NVRAM гостя чекпоинт и экспорт Hyper-V.** Шаг В.
5. **Дефект B ещё не воспроизведён на стенде.** Критерий готовности шага В.

## Возможности сократить время, отложенные осознанно

Автор просил не упускать такие и разбирать их, когда они появляются.
Обе стоит сделать в конце шага Б, когда сборка носителя устоится.

- **`boot.wim` несёт два образа, а нужен один.** Индекс 1 — чистый WinPE,
  индекс 2 — установщик Windows. Пользуемся вторым, первый едет мёртвым грузом,
  а образ при загрузке целиком уезжает в оперативную память. Убирается экспортом.
- **`install.wim` содержит два издания.** Домашнюю мы не поддерживаем: на ней
  не ставится Atlas. Экспорт только Pro сократит носитель примерно вдвое.

## Как проверять окно на обычной Windows

Приложение не установлено в системе, общие средства управления экраном его
не видят. Работает другое, всё проверено на шаге А:

- **снимок окна** — `PrintWindow` с флагом `PW_RENDERFULLCONTENT` (значение 2);
- **управление** — UI Automation из PowerShell (`UIAutomationClient` + `UIAutomationTypes`);
- **строки списка с колонками** отдаются типом `DataItem`, а не `ListItem`;
- **нажатие кнопки, открывающей модальное окно, блокирует поток** — нажимать
  надо из отдельного процесса, модальное окно искать по классу `#32770`;
- **запущенное из фоновой оболочки окно приходит свёрнутым** — разворачивать
  `ShowWindow(h, 4)`, это `SW_SHOWNOACTIVATE`;
- по той же причине **не предлагай автору кнопку «Запустить»** у блока
  с командой запуска приложения — окно уедет в панель задач.

## Как работать над этим проектом

Прямые указания автора. Соблюдай их.

- **Объясняй приземлённо.** Не «NVRAM хранит BootOrder», а «материнская плата
  помнит, откуда грузиться». Термин вводи один раз и сразу переводи.
  При выборе из вариантов пиши конкретно: что делаю я, что делаешь ты,
  сколько времени, что получишь, что при этом плохо.
- **Качество и логика важнее краткости.** Думать столько, сколько нужно.
  Но воду не лить: автор об этом просил отдельно.
- **Никакой кустарщины.** Только систематические решения на долгую жизнь.
- **Дробить на подзадачи.** Понемногу, постепенно.
- **Сначала видимое, потом оснастка.**
- **Не отбирать у пользователя возможности** со словами «это вам не нужно».
- **Спрашивать, если ответ меняет архитектуру.** Не угадывать.
- **Проверять на живом железе.** Все три дефекта шага А и обе ошибки этой
  сессии нашлись при запуске, а не в тестах.
- **Не выдавать чужую проверку за свою** и не выдавать догадку за факт.
  Если что-то может подтвердить только автор — скажи прямо и дождись.
- **Не упускать возможности оптимизации,** но и не выдумывать их там, где их нет.
