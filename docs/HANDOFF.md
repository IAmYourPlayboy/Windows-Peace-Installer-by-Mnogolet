# Часть третья: что сделано этой сессией и почему

Шесть коммитов. Два из них — прямые решения автора, принятые по ходу.

## Экран «Что ставим» (задача 10)

Список рецептов с носителя: название, издание Windows, объём образа, описание.
Ничего не выбирает за человека даже тогда, когда рецепт единственный. Список
не синхронизируется с «текущим элементом» — иначе первая строка оказалась бы
выбранной сама.

Все четыре беды с описью приводят на этот же экран: объяснение словами
и выключенная кнопка «Далее». **Из тупика есть выход** — кнопка «Закрыть
мастер»: в WinPE окно занимает весь экран и креста на нём нет.

## Решение автора: человеку — объяснение, нам — журнал

Дословно: «Дефолтный человек из интернета в рот ебал разбираться что у нас
за баги — только мы должны эти баги исправлять. Журнал не нужен человеку —
только нам».

Отсюда три правки:

- **Технический текст на экран не выносится.** Разбор описи отказывал человеку
  фразой «Expected depth to be zero at the end of the JSON payload» — по-английски
  и ни о чём. Теперь `MediaManifestResult` несёт два поля: `Message` для человека
  и `Detail` для журнала.
- **Служебная фраза** «Хеши заполняются автоматически…» ушла из описания рецепта
  (человек читал её на первом экране) в описание поля схемы рецепта.
- **Неожиданная ошибка** не выходит человеку системным окном .NET с трассировкой.
  Одна строка по-русски, всё остальное в журнал, мастер закрывается сам.

## Решение автора: журналу всегда есть куда писать

Дословно: «либо делай так чтобы можно было всегда куда-то писать, либо файл
чтобы не был постоянно занят… дабы в будущем это не ебало бошку нам».

Прежний порядок сначала проверял пробным файлом, можно ли писать, а открывал
файл потом — и в промежутке файл успевал стать занятым. Теперь проверка и есть
открытие: `OperationLogOpener` перебирает места (рядом с приложением,
оперативный диск, временная папка), в каждом — пять имён. Что не подошло
и почему, уходит первыми записями в открывшийся журнал.

`LogLocationResolver` с пробным файлом удалён вместе с тестами: два способа
делать одно дело — заведомое расхождение.

Проверено вживую двумя мастерами разом: второй пишет в `windows-peace-2.jsonl`
и объясняет в первой записи, почему не в первый.

## Дефект, найденный проходом по написанному

**Журнал мог уронить мастера.** Запись доводится до носителя; носитель могут
вынуть на середине работы, а фоновая задача — дописать что-то уже после того,
как журнал закрыли на выходе. Отказ летел наружу посреди установки. Теперь
журнал в таком случае молча замолкает — сказать о беде ему нечем, единственное
место, куда он умеет говорить, и есть отказавший файл.

## Мелочи того же прохода

- Форматирование размеров было написано дважды слово в слово и просилось
  в третий раз — свёл в `ByteSize` в ядре. В `DiskDump` формат **нарочно**
  оставлен свой, причина записана в коде.
- Цвет беды `#B00020` стоял числом в двух разметках — стал общей кистью.
- `ByteSize` показывал «0 МБ» там, где что-то есть, — теперь «менее 1 МБ».
- `DiskDump` открывал журнал в лоб и падал бы на занятом файле.
- Сборщик носителя не писал в опись объём образа — столбец «Объём» на настоящем
  носителе пустовал.

## Отступления от плана — и почему

| Что в плане | Что сделано | Причина |
|---|---|---|
| `MediaLocation.ManifestFileName` | `MediaLayout.ManifestFileName` | план писался до переезда раскладки |
| своё форматирование размера в строке рецепта | общий `ByteSize` | иначе третий вариант того же самого |
| `ObservableCollection` для рецептов | `IReadOnlyList` | список после чтения описи не меняется |
| только текст беды на экране | текст плюс кнопка «Закрыть мастер» | спека требует «предлагает закрыть мастер» |
| — | `HasRecipes` прячет пустую таблицу | пустая таблица с заголовками ничего не объясняет |
| преобразователи в разметке страницы | в `App.xaml` | нужны уже двум экранам |

# Часть четвёртая: что знать о проекте и машине

## Что за проект

Windows Peace — инструмент развёртывания настроенной Windows 11. Три части:
`Studio` (готовит флешку), `Setup` + `Agent` (мастер установки и доводка),
мини-сайт документации. Общие для всех — `WindowsPeace.Core` и файл рецепта.

Проект меценатский: планируется сайт, где незнакомым людям бесплатно предлагают
установить настроенную систему. Отсюда все решения в пользу осторожности.

## Права администратора

**Нужны.** Проверить:

```powershell
([Security.Principal.WindowsPrincipal][Security.Principal.WindowsIdentity]::GetCurrent()).IsInRole([Security.Principal.WindowsBuiltInRole]::Administrator)
```

Если `False` — приложение Claude надо завершить **полностью через значок
у часов**, а не закрыть окно, и запустить правой кнопкой → «Запуск от имени
администратора». Закрытие окна процесс не завершает. Запасной путь: автор
открывает «Терминал (Администратор)» и запускает оттуда
`%APPDATA%\Claude\claude-code\<версия>\claude.exe --resume`.

## Решения автора — не переспрашивай

| Вопрос | Ответ |
|---|---|
| Версия Windows | Windows 11 Pro 25H2, `isoInjection` для Atlas доступен |
| Режим загрузки | Только UEFI + GPT |
| Базовый образ | `boot.wim` из установочного ISO, индекс 2 |
| Устройство носителя | Два раздела: FAT32 «системный EFI» без буквы + NTFS с буквой |
| Где живёт приложение | Рядом с `boot.wim`, а не внутри него |
| Перечисление дисков | Прямой разговор с Windows, без WMI |
| Чем проверять | Виртуалка для круга, настоящая флешка в конце шага |
| Экран выбора рецепта | Входит в шаг Б |
| Загрузочный носитель в списке | Виден, но серый и с объяснением. Ничего не скрывать |
| Разделы в интерфейсе | Список двухуровневый, кнопки операций остаются |
| Раскладка экрана | По смыслу как в установщике Windows. Визуал автор настраивает сам |
| Среда выполнения | Самодостаточное .NET 8, **не в один файл** |
| Целевые платформы | `Core` — `net48;net8.0-windows`, `Setup` — только `net8.0-windows` |
| Ветки и отправка | Отдельная ветка, слияние в `main` и отправка в конце шага |
| **Что видит человек при беде** | **Объяснение своими словами. Тексты чужих библиотек, пути, коды отказов — только в журнал** |
| **Журнал** | **Человеку о нём не рассказываем. Наше дело — чтобы место для записи находилось всегда** |

## Открытые вопросы

Не выдавай их за решённые.

1. **Хватит ли цепочки запасных шрифтов** на настоящем железе. В виртуалке
   текст читается, но обычного Segoe UI в образе нет. Сама цепочка ставится
   задачей 12 — в CLAUDE.md это записано честно как «будет».
2. **Перекроет ли `winpeshl.ini` запуск установщика Windows,** или придётся
   править куст реестра внутри образа. Задача 13, там же запасной приём.
3. **Как поведут себя настоящие прошивки** с разделом «системный EFI»
   на съёмном носителе. На виртуалке — образцово.
4. **У виртуальных дисков Hyper-V нет серийного номера,** отпечаток честно
   откатывается на разметку. Стенд не годится для проверки отпечатков.
   Важно для шага В.
5. **Дефект B ещё не воспроизведён на стенде.** Критерий готовности шага В.
6. **`WmiDiskEnumerator` больше не используется приложением,** но оставлен ради
   сличения в `DiskDump`. Убирать ли его вместе с зависимостью
   от `System.Management` — спросить автора в конце шага.
7. **Сличение дисков показывает четыре расхождения** — у разделов без буквы WMI
   не знает файловую систему, а прямой путь знает. Похоже на превосходство
   прямого пути, но автором это не подтверждено; проверять на живом железе.
8. **Ветка «выхода из мастера» есть только на экране 1.** В полноэкранном
   режиме WinPE креста нет ни на одном экране. Задача 12 — самое время
   спросить автора, нужен ли выход везде.
9. **Объём образа в описи** впервые отработает только на настоящей флешке
   (задача 14): на стенде `install.wim` не копируется, и размер не пишется.

## Возможности сократить время, отложенные осознанно

Обе стоит сделать в конце шага Б.

- **`boot.wim` несёт два образа, а нужен один.** Индекс 1 — чистый WinPE,
  индекс 2 — установщик Windows. Первый едет мёртвым грузом, а образ при
  загрузке целиком уезжает в оперативную память. Убирается экспортом.
- **`install.wim` содержит два издания.** Домашнюю мы не поддерживаем: на ней
  не ставится Atlas. Экспорт только Pro сократит носитель примерно вдвое.

# Часть пятая: как работать с автором

Зовут **razvert** (в проекте — Mnogolet). Соло-разработчик, пишет по-русски,
разбирается в предмете, но не любит, когда с ним говорят терминами.
Хвалит эмоционально и матом — это одобрение, а не тревога.

Прямые указания, соблюдай их:

- **Объясняй приземлённо.** Не «NVRAM хранит BootOrder», а «материнская плата
  помнит, откуда грузиться». Термин вводи один раз и сразу переводи.
  Варианты описывай действиями и минутами.
- **Качество и логика важнее краткости.** Думать сколько нужно. Воду не лить.
- **Никакой кустарщины и захардкоженного.** Только систематические решения
  на долгую жизнь.
- **Дробить на подзадачи.** Понемногу, постепенно.
- **Сначала видимое, потом оснастка** — но если оснастка уже нужна для работы,
  делать её сразу и хорошо.
- **Не отбирать у пользователя возможности** со словами «это вам не нужно».
- **Спрашивать, если ответ меняет архитектуру.** Не угадывать.
- **Проверять на живом железе.** Все дефекты этого проекта нашлись при запуске,
  а не в тестах.
- **Не выдавать чужую проверку за свою** и догадку за факт.
- **Не упускать возможности ускорить,** но и не выдумывать их там, где их нет.
- **Проход по написанному перед каждой остановкой** — системность,
  универсальность, хардкод, баги. Это правило он дал прямо.

Отчитываться после каждой задачи плана: что сделал, что нашёл, что проверил,
что дальше. Отступления от плана называть и объяснять.
