## Ключевые выводы — не переоткрывай их заново

### 1. Настоящий баг — не DiskID

Автор жаловался, что установка уходит не на тот диск, и лечил это отключением дисков. Но из его описания вылез **второй, отдельный дефект**, который и составляет основную часть боли:

> поставишь Win11 Pro с autounattend → оно что-то сделает, перезагрузится → **при загрузке всё та же Win10 Pro**

Windows 11 при этом устанавливается нормально. Машина грузит не её, потому что Setup пишет загрузчик в первый найденный EFI-раздел и не правит порядок загрузки в NVRAM прошивки. Старая запись остаётся первой.

Форматирование всех дисков установщиком Win10 «помогает» по случайности: уничтожает конкурирующий ESP.

**Статус:** это обоснованная гипотеза, выведенная из описания и механики Windows Setup, но она **ещё не воспроизведена**. Сценарий «грязная машина» в Фазе 0 существует именно для того, чтобы её подтвердить. Не считай её доказанной до этого.

### 2. autounattend автора конфликтует с Atlas

Сейчас он ставит Windows с autounattend, который «вырезает всю хуйню», а потом поверх накатывает Atlas. Atlas официально требует **чистую немодифицированную** Windows; предварительный дебloat ломает логику плейбука.

Отсюда решение: `unattend.xml` делается тонким (только локаль, аккаунт, пропуск OOBE, при необходимости обход проверок железа), всё остальное переезжает в агент и выполняется **после** Atlas.

### 3. «WinHawk» — это Windhawk

[ramensoftware/windhawk](https://github.com/ramensoftware/windhawk). Ставится silent'ом (`winget install RamenSoftware.Windhawk --silent`, либо NSIS `/S /STANDARD`). Самая простая часть пайплайна.

### 4. Atlas не автоматизируется полностью

У AME Wizard нет документированного CLI. Есть три пути, все заложены в схему как стратегии с мягкой деградацией:

- `isoInjection` — [официальный](https://docs.atlasos.net/getting-started/install/install-iso-injection/), автоматический, но **экспериментальный**: только Win11 25H2 и Playbook 0.5.0+, Home не поддерживается, нужен интернет;
- `wizardUi` — прокликивание через `System.Windows.Automation`, ломается при обновлении их интерфейса;
- `wizardAssisted` — агент готовит всё, человек нажимает несколько кнопок.

**Не обещай автору zero-touch по Atlas.** Даже `wizardAssisted` срезает большую часть трёх часов.

## Следующий шаг

**Задача 2, Фаза 0 — стенд Hyper-V.** Конкретно:

- PowerShell-модуль в `test/`: создание VM с UEFI, Secure Boot, TPM;
- **четыре виртуальных диска разного размера** — без этого логику выбора диска проверить нечем;
- монтирование ISO, снапшоты для мгновенного отката;
- сценарий «грязная машина»: предустановленная Win10 с собственным ESP на одном из дисков — воспроизведение дефекта из вывода 1;
- цель: одной командой поднимается чистая машина, одной — грязная.

Дальше Фаза 1 — спайк WinPE + WPF. Он снимает главный технический риск: **WPF в WinPE официально Microsoft не поддерживается.** Практики сообщают, что работает с компонентом `WinPE-NetFx`, но пока это не проверено своими руками — не строй на этом UI. Если не заработает, запасные варианты HTA и WinForms.

## Как работать над этим проектом

Прямые указания автора, соблюдай их:

- **Качество и логика важнее краткости.** Думать столько, сколько нужно; скорость не важна.
- **Никакой кустарщины.** Только систематические решения, рассчитанные на масштабирование и долгую жизнь.
- **Дробить на подзадачи.** Делать понемногу, постепенно, а не вываливать всё разом.
- **Брейнштормить, когда задача того требует.** Задавать уточняющие вопросы, если ответ меняет архитектуру.
- **Держать в голове структуру проекта** и работать с ней аккуратно.

Технические принципы, вытекающие из архитектуры:

- Конфигурация живёт **только** в рецепте. Новый профиль установки — новый JSON, а не правка кода.
- Новая возможность пост-установки — **новый тип шага**, движок не трогается. `script.run` — аварийный люк; если туда попадает что-то повторяющееся, значит нужен типизированный шаг.
- Диск **нигде** не адресуется порядковым номером. Только отпечаток.
- Дефолты выбираются в пользу безопасности: инструмент форматирует диски с чужими данными.
- Полезная нагрузка (ISO, Atlas) **не хранится в репозитории**, только скачивается с проверкой SHA256.
